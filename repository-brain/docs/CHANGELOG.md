# Changelog

All notable changes to Repository Brain are documented here.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

- **Scaffold** — uv-managed Python 3.12+ project with FastAPI, SQLAlchemy 2.x,
  pydantic-settings, structlog, Alembic and Docker.
- **Migrations** — Alembic environment wired to application settings with an
  autogenerated initial revision covering all ten tables; verified `upgrade head`.
- **Documentation** — README plus `docs/` (architecture, API, database, roadmap,
  contributing, changelog) and an MIT `LICENSE`.
- **Examples** — `examples/index_repo.py` shows programmatic register/index/query.
- **Configuration** — typed settings loaded from environment variables
  (`repository_brain/core/config.py`) with SQLite development default and PostgreSQL production URL.
- **Models** — UUID-keyed SQLAlchemy ORM models for repositories, files, symbols,
  dependencies, modules, architecture and memory.
- **Scanner** — incremental file scanner with SHA-256 content hashing and an
  `(mtime, size)` fast path; default ignore rules for build artifacts, VCS and
  dependency directories.
- **Parser** — tree-sitter based extraction of symbols, imports and call sites for
  Python, TypeScript, JavaScript, React (TSX/JSX), JSON, YAML and Markdown.
  Class/method hierarchy via a parent stack; JSX-returning functions promoted to
  components.
- **Symbol engine** — replaces symbols per file with parent/child hierarchy and
  qualified names.
- **Dependency engine** — import, call and inheritance edges with path resolution,
  including relative imports and a suffix fallback for `src/`-style layouts.
- **Module detection** — logical grouping of files by directory with role scoring.
- **Architecture detection** — languages, frameworks, manifests, entry points,
  patterns and conventions.
- **Memory engine** — persistent repository memory with rule-based summaries,
  module summaries, statistics and conventions. Rebuilt only on explicit request.
- **Snapshots** — full index serialised as JSON under `<repo>/.brain/` (or managed
  storage when the repository is not writable).
- **Search** — SQL-backed search across symbols, files, modules and dependencies
  (no embeddings required).
- **REST API** — repository CRUD and scanning, search, symbols, files, modules,
  dependencies, summary/architecture/statistics and health endpoints.
- **Tests** — 52 unit and integration tests covering the scanner, parser, resolver,
  engines, indexer, memory, search and API.
- **Linting** — ruff configured with a curated rule set; formatting enforced.

### Fixed

- Reserved SQLAlchemy attribute name `metadata` renamed to `extra` on models.
- Module symbol counting uses a real `func.count()` instead of an invalid scalar count.
- Parser: bytes/str visibility handling, import extraction for Python dotted and
  aliased imports, TS/TSX import clause handling, and JSX component detection.
- Dependency model ambiguity resolved by explicit `foreign_keys` on relationships.
- Scanner now ignores the `.brain` snapshot directory and counts only indexed files.
- Search binds UUID repository ids correctly.
- Repository memory is now created once and preserved across scans; it is rebuilt only
  on an explicit `POST /memory/refresh`, matching the documented persistent-memory policy.

### Changed (OpenAI-compatible proxy)

- Added `GET /api/v1/models` — OpenAI-compatible model listing advertising
  `OPENAI_ADVERTISED_MODEL` (default `repository-brain-v1`); served locally and never
  requires the upstream LLM backend.
- `GET /health` is now a pure liveness probe returning `{"status": "ok"}` and no longer
  depends on database or LLM backend connectivity.
- New `OPENAI_ADVERTISED_MODEL` setting (`.env.example`, `docs/API.md`, README) for the
  model name advertised to clients; distinct from `OPENAI_MODEL` (upstream model).
- The Python package was renamed from `app` to `repository_brain` so the application
  starts with `uv run uvicorn repository_brain.main:app`. All imports, the console
  script, Alembic env, Dockerfile, examples and tests were updated accordingly.
- Settings now use `NoDecode` for `ALLOWED_REPOSITORY_ROOTS` so an empty
  `.env` value (`ALLOWED_REPOSITORY_ROOTS=`) loads cleanly instead of crashing startup.
- Dockerfile rebuilt on the official `uv` runtime (`ghcr.io/astral-sh/uv`) with a locked
  install; `docker-compose.yml` now reads configuration from environment variables with
  no hardcoded secrets, exposes port 8000, and keeps the Qwen backend as a separate
  process pointed to via `OPENAI_BACKEND`.
- Added `.dockerignore` so `.env` secrets and local caches never enter the build context;
  Dockerfile `COPY` paths updated to the `repository_brain` package name.
- Test suite now runs clean with zero warnings: upstream
  `starlette.exceptions.StarletteDeprecationWarning`s (TestClient import and a deprecated
  status constant used by Starlette's own exception handlers) are suppressed in
  `pyproject.toml` `filterwarnings`.
- Added `scripts/qwen_stub.py` — a deterministic OpenAI-compatible stub backend for
  reproducible manual verification of the relay when no real LLM server is installed
  (documented in the README under "Verifying without a real LLM").
- Documentation expanded with Qwen startup, Roo Code configuration, curl examples,
  streaming, troubleshooting and testing sections.
